# Hdiff

폐쇄망에서 HWP/HWPX/Word/PDF/Excel/TXT/Markdown 문서 또는 직접 붙여넣은 텍스트의 변경 내용을
좌·우 원문 비교 화면으로 보여 주는 Windows 네이티브 도구입니다. 원본 파일은 수정하지 않습니다.

## 현재 구현 범위

- WinForms: 전/후 파일을 첨부 카드에 드래그하면 즉시 읽기 확인을 하고, 파일
  크기·확장자·추출 글자 수·문단 수·사용 파서를 표시. **직접 입력**에서는 AI 응답이나
  Markdown·일반 텍스트를 디스크 임시파일 없이 붙여넣어 파일과 교차 비교 가능
- 상단 **글자 크기**: 작게(12px)·보통(14px, 기본)·크게(16px). 선택값은
  `%LocalAppData%\Hdiff\settings.json`에 저장되어 새 배포본으로 바꿔도 유지
- 비교 본문은 한글 보고서 가독성을 위해 `맑은 고딕`과 넉넉한 행간을 기본 사용
- 상단 **화면 테마**: 기본 화이트 또는 Rust 스타일의 블랙(네이비) 테마. 첨부 카드,
  비교 행, 인라인 강조, 미니맵까지 함께 전환하며 선택값은 글자 크기와 같이 저장
- 기본 활성화된 **빈 개행(엔터) 무시**: 내용 없는 문단을 문단 대응과 변경 요약에서
  제외. 체크를 풀면 원래 빈 문단도 비교 행으로 표시
- 설정의 **Document Content → Include Memos**: 기본값은 해제이며 원본 문서에 이미 달려
  있는 HWP/HWPX 메모를 본문에서 제외. 그 메모 자체를 비교해야 할 때만 켜며 선택값은
  사용자 설정에 저장. 직접 파서에만 적용되고 COM 폴백에는 적용되지 않으며, 폴백에 메모가
  있으면 건수를 경고로 알림. Hdiff에서 다는 아래의 **검토 메모**와는 별개의 설정
- 좌·우 문단 정렬 비교, 줄 번호 및 문자 단위 강조 (삭제는 빨강, 추가는 초록)
- 기본 활성화된 Google Diff Match Patch semantic cleanup: 수정으로 대응된 문단 안의
  강조 범위를 읽기 좋게 정돈. 체크를 풀면 기존 DiffPlex 문자 강조와 직접 비교 가능
- 기본값으로 긴 줄 자동 줄바꿈. 비교 결과를 행별 데이터로 만든 뒤 하나의 가상
  캔버스에 좌·우를 함께 그리므로, 삽입·삭제와 줄바꿈 뒤에도 두 쪽이 같은 표시 행과
  같은 y좌표를 공유한다. 필요하면 체크를 풀어 가로 스크롤로 전환
- 각 비교창 오른쪽: 문서 전체의 줄 길이와 변경 위치를 압축한 미니맵. 수천 문단에서도
  변경 위치가 보이도록 1px 단위의 고대비 변경 신호 막대가 있으며, 미니맵을
  클릭하거나 끌면 해당 위치로 이동
- **검토 메모**: Word·Excel·한글의 메모처럼 개별 변경 행에 검토 의견을 남김. 비교 행의
  호버 `+`, 마우스 오른쪽 클릭 또는 `Ctrl+M`으로 작성. 별도 창 대신 오른쪽 320px
  카드 패널에서 인라인으로 메모를 작성·편집하고 기존 메모에는 회신도 추가. **메모를 다는 쪽이 곧
  대상**이어서, 왼쪽에서 달면 변경 전 문단에 대한 메모, 오른쪽에서 달면 변경 후 문단에
  대한 메모가 되고 표식도 그쪽에만 붙음(한쪽이 비어 있는 행은 글이 있는 쪽으로 자동 보정).
  **문구를 드래그해 선택한 뒤 메모를 달면 그 구간에 메모가 붙습니다.** 본문의 그 글자에
  주황색 밑줄과 옅은 배경이 그려져 어느 대목인지 열어 보지 않아도 보이고, 카드는 그 문구만
  인용해 "여기 이 문구가~" 식으로
  가리킬 수 있음. 선택 없이 달면 인용을 붙이지 않아 메모 내용이 바로 보임 — 문단 전체를
  되풀이하면 정작 메모가 묻히기 때문. 선택한 문구가 그 문단에 없거나 문단 전체와 같으면
  인용으로 받아들이지 않고, 앞뒤 공백은 다듬어 저장하며, 다시 비교했을 때 그 문구가
  사라졌으면 표시만 조용히 떼어 내고 메모는 문단에 남김. 같은 낱말이 한 문단에 여러 번
  나오면 문구가 아니라 **위치**로 가려내므로 엉뚱한 쪽에 표시되지 않음. 구간은 한 비교 칸
  안으로 제한되며(여러 행에 걸친 선택은 무시), 줄바꿈으로 문단이 여러 줄에 걸쳐도 표시가
  이어짐. 공유 HTML도 같은 구간을 `<mark>`로 그대로 표시함(단, 받는 사람이 HTML 안에서
  새로 다는 메모는 아직 인용만 남고 본문 표시는 없음)
  메모가 달린 칸에는 주황색 세로 표시와 개수 배지가 붙고, 배지를 누르면 오른쪽 메모 카드가
  선택됨. 카드를 고르면 해당 문단으로 이동하고 본문 표식과 점선으로 이어짐. 회신 작성자별
  색상은 HTML과 같은 8색 팔레트를 사용. 원본 문서는
  건드리지 않고 비교 세션에만 존재. 비교 옵션을 바꿔 다시 비교해도 메모는 문단 본문을
  기준으로 같은 문단을 따라가며, 그 문단이 사라진 메모는 엉뚱한 행에 붙이지 않고
  `위치 없음`으로 남김. 미추출 검토 내용이 있으면 앱 종료나 문서 교체 전에 경고하고,
  확인 후 전/후 문서를 바꾸면 새 검토로 보고 메모를 비움
- 비교 완료 후 **HTML 추출**: 현재 비교 결과를 외부 파일 의존성이 없는 단일 HTML로
  저장. 원본 HWP/HWPX나 Hdiff가 없는 PC에서도 브라우저로 좌우 비교·동기 스크롤·변경
  미니맵·본문 복사를 사용할 수 있고, 저장 당시 테마·글자 크기·줄바꿈 설정을 그대로 반영.
  검토 메모가 있으면 오른쪽에 메모 패널이 함께 담기고, 본문의 메모 번호 배지를 누르면
  해당 메모로, 메모 카드를 누르면 해당 문단으로 이동. 선택한 메모는 본문 표식과 점선으로
  이어져 어느 문단의 메모인지 한눈에 보이며, 선은 하나씩만 그려 교차로 지저분해지지 않음
- **HTML에서 회신·메모 추가(왕복 검토)**: 추출한 HTML을 받은 사람이 브라우저에서
  각 메모에 `회신`을 달거나, 비교 행 오른쪽에 뜨는 `+`로 **새 메모**를 직접 달 수 있음
  (마우스가 올라간 쪽이 그대로 변경 전/후 대상이 됨). 여러 건을 먼저 다 쓴 뒤
  `회신 저장`을 한 번 누르면 그 상태가 반영된 HTML 파일로 저장됨(`…_회신1.html`,
  다시 회신하면 `_회신2`). Chrome·Edge에서는 **저장 위치를 고르는 대화상자**가 뜨고 고른
  파일을 기억해 다음 저장부터 같은 파일에 덮어쓰며(`위치 변경`으로 다시 고름), 이 API가
  없는 브라우저에서는 기존처럼 내려받기 폴더로 저장됨. 저장 후에는 패널에 파일명과 시각을
  표시. 웹 페이지는 방금 쓴 로컬 파일을 열 수 없으므로 Hdiff 본체의 `HTML 추출`과 달리
  `저장 후 열기`는 없음(보고 있는 탭이 곧 저장된 내용). 그 파일을 회신하면 됨. 저장 전에는 파일에
  아무것도 쓰지 않으므로 `저장 안 됨` 표시가 뜨고, 저장하지 않은 채 창을 닫으면 브라우저가
  경고. 회신과 새 메모는 DOM에 남아 같은 파일을 다시 열어도 유지되고, 작성자 이름별로
  8색 팔레트에서 색이 배정되어 MS Office 회신처럼 누가 쓴 글인지 색으로 구분됨. 받은
  사람이 지울 수 있는 것은 자기가 추가한 메모·회신뿐이며 원 작성자의 메모는 읽기 전용.
  검토 메모 없이 추출해도 패널은 접힌 채 함께 담기므로 받는 사람이 처음부터 메모를 달 수
  있음. 서버·네트워크·외부 스크립트 없이 파일 하나로 동작하며, `localStorage`나 클립보드
  API처럼 `file://`에서 막히는 경로는 쓰지 않음. 회신이 담긴 HTML을 Hdiff로 다시 불러오는
  기능은 두지 않음 — Hdiff는 원본 두 파일에서 비교를 매번 새로 만들고, 회신은 HTML 안에서
  계속 왕복되므로 기능이 겹침
- HWPX: ZIP/XML 직접 파싱 (한글 불필요)
- HWP5: OLE Compound File → `FileHeader`/`BodyText/Section*` → 압축 해제 →
  문단 text record 직접 파싱 (한글 불필요). 한글 2018의 `%unk`/`MEMO` 필드와
  일반 HWP5 메모 컨트롤의 하위 문단을 본문과 구분
- TXT/Markdown: UTF-8·BOM이 있는 UTF-16·CP949를 줄 단위로 읽고 Markdown 문법은 원문 그대로 보존
- Excel (`.xlsx`, `.xls`, `.xlsm`, `.xlsb`): 별도 워커가 새 Excel COM 인스턴스를 만들어
  매크로·외부 링크를 끄고 읽기 전용으로 열어 DRM 문서도 원본 변형 없이 읽음. 시트명과
  숨김 상태를 헤더로 보존하고, 같은 행의 셀은 ` | ` 경계로 비교하며 완전히 빈 행은 한
  시트 안의 여러 표를 나누는 경계로 사용. 수식 자체가 아니라 Excel이 계산한 셀 값을 비교.
  내부 정렬용 시트·표 표식은 화면에서 숨기고, 시트명은 헤더로 표시
- Word (`.docx`): 별도 워커가 새 Word COM 인스턴스를 만들어 매크로·링크 갱신을 끄고
  읽기 전용으로 열어 DRM 문서도 원본 변형 없이 읽음. 본문과 표의 원래 순서를 보존하며
  표 셀 내부 개행은 공백으로, 같은 행의 셀은 ` | ` 경계가 있는 한 비교 행으로 처리
- PDF (`.pdf`): DocMine에서 검증한 순수 관리형 PdfPig로 단어 좌표를 위→아래·좌→우
  읽기 순서의 비교 행으로 재구성. PDF 본문은 UI가 아닌 격리 워커만 읽으며, 배포본은
  운영 DRM의 프로세스 basename 조건에 맞춘 동일 바이너리 `python.exe`를 PDF 워커로 사용.
  스캔 이미지 PDF는 OCR을 적용하지 않으므로 텍스트 본문이 없다는 오류를 표시
- 설정의 **Document Content → Reflow PDF Paragraphs**(기본 켜짐): PDF가 주는 것은
  논리적 문단이 아니라 인쇄된 줄이라, 문단 앞쪽 낱말 하나만 바뀌어도 뒤따르는 줄바꿈이
  전부 밀려 문단 전체가 바뀐 것처럼 보임(재접힘 연쇄). 이 옵션은 접힌 줄을 원래 문단으로
  되돌린 뒤 비교함. 판정은 좌표로만 함 — 접힌 줄은 본문 오른쪽 여백선까지 닿고 문단 끝
  줄은 못 미친다는 성질을 쓰며, 여백선은 그 쪽의 줄들에서 직접 구하고 허용 오차는 평균
  글자 폭 기준으로 잡음. 줄 간격이 벌어지거나 다음 줄이 들여쓰기·`제N조`·번호·글머리표로
  시작하면 새 문단으로 끊음. 한글은 공백 없이, 로마자는 공백을 넣어 잇고 줄 끝 하이픈은
  제거함. **가릴 수 없는 문서(개조식·표·서식처럼 줄이 여백선에 못 닿는 경우)에서는 아무것도
  병합하지 않아 옵션을 끈 것과 같게 동작**하므로, 최악이 '개선 없음'이지 '더 망가짐'이 아님.
  LLM이나 외부 호출은 쓰지 않으므로 결과가 항상 재현되고 본문이 밖으로 나가지 않음
- DRM/DLP 안전 경계: 문서 본문은 UI가 아닌 자식 워커가 읽음
- COM 폴백: 직접 파서가 실패할 때만 한글 COM의 `InitScan`/`GetText` 메모리 스캔으로
  평문을 읽음. 보안 정책 팝업을 유발할 수 있는 `GetTextFile`, `Save`/`SaveAs`, 임시 HWPX,
  원본 잠금 파일을 만들지 않고, 사용자가 열어 둔 Hwp.exe를 찾거나 종료하지 않음. 표는
  스캔 위치의 셀 주소를 읽어 같은 행의 셀을 공백으로 잇고 행 사이만 개행함. 중첩 표는
  부모 행을 개행으로 닫은 뒤 독립 표처럼 행별 출력하고, 종료 후 부모 표 처리를 재개함.
  메모는 `HeadCtrl` 순회로 건수만 세어 경고하고 본문에 남겨 둠. `DeleteCtrl`로 지우면
  문서 수정 플래그가 서고, 메모 리스트만 따로 스캔하는 읽기 전용 경로는 측정한 모든
  실행에서 `COMException`이 발생해 둘 다 채택하지 않음.

HWP5 직접 파서는 현재 문단 중심입니다. 표의 셀 격자·글상자·각주·서식 차이는
후속 단계이며, 현재 표 안의 텍스트는 문단으로만 보일 수 있습니다.

## 실행

```powershell
dotnet run --project src/Hdiff.UI
```

Windows 탐색기에서 [run-ui.cmd](/C:/projects/hdiff/run-ui.cmd:1)를 더블클릭해도 됩니다.
이 배치 파일은 항상 현재 소스를 `dotnet run`으로 빌드·실행합니다.

전/후 영역에 지원되는 HWP/HWPX/Word/PDF/Excel/TXT/Markdown 파일을 놓고 **비교**를 누릅니다.
기본값은 직접 파서 실패 시에만 COM 폴백을 허용합니다.

## 자동 검증 및 생성되는 테스트 문서

```powershell
# 합성 HWP5, HWPX, diff 로그 생성 및 직접 파서 검증
dotnet run --project tests/Hdiff.Tests

# 한글 COM이 설치된 PC에서는 실제 HWP 생성 후 직접 파서까지 검증
```

## 배포

이 개발 PC에는 .NET 8 SDK만 있으므로 현재 프로젝트는 `net8.0`으로 빌드됩니다.
대상 폐쇄망의 .NET 9 SDK에서 반입 빌드를 할 때에는 `Directory.Build.props`의
`TargetFramework`을 `net9.0`으로, UI 프로젝트의 `net8.0-windows`를
`net9.0-windows`로 올리면 됩니다.

반입용 ZIP은 [build.cmd](/C:/projects/hdiff/build.cmd:1)로 만듭니다. Hdiff의 공식
배포 형식은 .NET Desktop Runtime을 쓰는 FDD ZIP 하나이며, 파일명은
`Directory.Build.props`의 `<Version>`에서 생성됩니다.

```cmd
build.cmd
REM publish\Hdiff-v0.1.0-win-x64-fdd.zip
REM .NET Desktop Runtime이 설치된 PC용의 작은 FDD ZIP
```

PDF DRM 비교를 위해 압축을 풀었을 때 `Hdiff.exe`와 같은 폴더의 `python.exe`를
삭제하거나 이름을 바꾸지 마십시오. 사용자는 `Hdiff.exe`만 실행하면 되며,
`python.exe`는 PDF를 읽을 때 백그라운드 워커로만 자동 실행됩니다.

`publish\fdd\`에는 압축 전 배포 파일이, `publish\` 바로 아래에는 반입용 ZIP이
저장됩니다. `pwsh -File publish.ps1`도 동일한 FDD ZIP을 생성합니다.

배포물의 공식 파일명은 `Hdiff.exe`입니다. 워커는 `Environment.ProcessPath`로
자기 자신을 다시 실행하므로, 앱과 워커는 항상 같은 실행 파일명으로 동작합니다.
